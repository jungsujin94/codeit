## 5. AI 가 만든 것과 확인 · 고친 것

| AI 가 만든 것 | 어떻게 확인했나 | 결과 · 고친 것 |
| --- | --- | --- |
| 저장 방식 제안 | 「코드 안에만 저장」은 Vercel 에서 서버가 쓴 파일이 사라져 「새로고침 후 유지」를 못 지킴을 확인 | Vercel Blob 으로 결정. 내 컴퓨터에서는 `.data/` 폴더로 같은 흐름을 확인 |
| `@vercel/blob` 설치 | npm 저장소 주소가 github.com/vercel/storage 인지 확인, 타입 정의(`put` · `get` · `list` · `del`)를 직접 읽음 | 고친 직후 옛 내용이 보이지 않도록 `get(..., { useCache: false })` 사용 |
| Next.js 16 사용법 | `node_modules/next/dist/docs` 의 Server Actions · 데이터 가져오기 · not-found · `serverActions.bodySizeLimit` 문서를 읽음 | `cacheComponents` 때문에 목록은 `<Suspense>`, 상세 · 수정은 `loading.tsx` 안에서 읽음. 그림 3MB 를 받으려고 bodySizeLimit 4mb |
| 신청서 오류 때 초점 옮기기 | 코드 검토 | 처음 판은 글을 고치는 동안에도 다음 틀린 칸으로 초점이 튀었음 → **보낸 뒤에만** 옮기도록 고침 |
| 신청서 다시 채우기 | React 19 는 form action 이 끝나면 신청서를 비움 → 서버 오류 때 쓴 글이 사라질 수 있음 | 직접 `startTransition` 으로 보내고 칸을 상태로 들고 있게 고침. 저장 실패를 일부러 만들어 글이 남는 것을 확인 |
| 상세 머리 배치 | 화면 확인 | 「← 목록으로」와 판정 표시가 한 줄에 붙음 → 줄을 나눔 |
| 그림 보내기 | 주소에 `../` 같은 값으로 다른 파일을 읽지 못하는지 검토 | id 는 UUID 모양, 그림 경로는 `images/…{jpg,png,webp}` 모양만 받도록 막음 |
| QA 표 | AI 가 처음에 확인하지 않은 줄까지 ✅ 로 적음 | 실제로 확인한 줄만 ✅, 나머지는 ⬜ 로 고친 뒤 배포에서 확인 |
